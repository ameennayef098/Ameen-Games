# خط إنتاج المحتوى

كيف يُملأ بنك الأسئلة حتى هدف 20,000 سؤال، وكيف يُعاد استئنافه بأمان.

## المبدأ: عملية واحدة، موجة واحدة، إلحاق فقط

كل البنية تحت `tools/`:

| الملف | الدور |
|---|---|
| `bulk_gen.py` | المحرك: المحفّزات، التحقق، البناء، الإلحاق المقفول |
| `gsema.py` | عدّاد تزامن مشترك **بين العمليات** لطلبات الـ API |
| `make_plans.py` | يبني خطط الموجات من **العدد الحالي** للبنك |
| `run_all_waves.py` | يشغّل كل الخطط في عملية واحدة |
| `run_wave.py` | يشغّل خطة واحدة (بديل أقدم) |
| `fill_categories.py` | يرفع الفئات الموجودة و/أو ينشئ فئات جديدة |
| `bench_gen.py` | يقيس الإنتاجية الفعلية قبل تحديد حجم الموجة |
| `dedupe_bank.py` | يزيل التكرار (إيقاف التوليد أولاً) |
| `apply_turnkeep.py` | سكربت الدفعة التي أضافت ميكانيكية احتفاظ الدور |

## سير العمل

```bash
python tools/bench_gen.py                 # قياس الإنتاجية الفعلية
python tools/make_plans.py                # يكتب data/waves/*.json
export AMEEN_API_SLOTS=6                  # الحد المشترك لكل العمليات
python -u tools/run_all_waves.py --workers 6
```

للمتابعة: `tail -f data/waves/logs/orchestrator.log` و `cat data/waves/_progress.json`.

## الإنتاجية المقاسة

قيست قبل الالتزام بحجم الموجة (4 عمّال):

| اللعبة | سؤال/دقيقة | كلفة السؤال الواحد |
|---|---|---|
| س.ج (API واحد لكل ~13 سؤال) | ~200 | 1x |
| حروف — سهل | ~54 | ~4x |
| حروف — صعب | ~33 | ~6x |

الحروف تحتاج **API لكل دفعة** (كلمات حقيقية أولاً، ثم سؤال لكل كلمة)، ولهذا تكلفتها
4–6 أضعاف. عند توزيع هدف كبير، ضع الحصة الأكبر على فئات س.ج وأبقِ حصة الحروف متواضعة
إلا إذا كان لديك ساعات.

**حساب الوقت:** `مجموع_الطلبات × متوسط_الثواني / عدد_المنافذ` — وليس `الأسئلة / (سؤال/دقيقة)`
لأن الثاني يتجاهل أن الحروف تهيمن على عدد الطلبات.

## حد التزامن: 6 منافذ (مهم)

`AMEEN_API_SLOTS` يحدّ طلبات الـ API المتزامنة **عبر كل العمليات**. القياسات:

| المنافذ | النتيجة |
|---|---|
| 6 | مستقر، ~60–130 سؤال/دقيقة، بلا 429 |
| 12 | عواصف 429، انخفض إلى ~1 سؤال/دقيقة |

أكثر من ~6 متزامنة تُشعل تحديد المعدل. **لا ترفعها.**

## عدّاد التزامن — خطآن حقيقيان

`tools/gsema.py` يحتاج **قفلين**:

1. **`msvcrt.locking` لا ينتظر — يرمي خطأ.** أقفال ويندوز للبايتات إلزامية، فالثريد الثاني
   **بنفس العملية** يحصل على `PermissionError` بدل الانتظار. بدون `threading.Lock` محلي
   حول قسم القفل الحرج، كل محاولة محتجزة كانت ترمي، وحلقة إعادة المحاولة تحوّل كل رمي
   إلى ثوانٍ من `time.sleep` — فتجمّد التوليد بعد دفعات قليلة.
2. **علامة "محتجَز" يجب أن تكون `threading.local()`.** خاصية نسخة عادية مشتركة بين كل
   الثريدات، فكان تسجيل تحرير ثريد يمسح علامة ثريد آخر → منفذه لا يتحرر أبداً والعدّاد
   يعلو حتى تتوقف كل عمليات الاستحواذ.

القفل الملفّي يُمسَك **فقط** أثناء قراءة-تعديل-كتابة العدّاد، أبداً لا أثناء طلب شبكة.

**القتل يتسرّب منافذ:** قتل عملية توليد يترك منافذها محجوزة (العدّاد لا يُنقص أبداً).
صفّر الملف إلى `0` بعد قتل العمليات، وأبقِ مهلة الاستحواذ قصيرة (~120 ثانية).

## التحقق قبل التخزين

كل عنصر يمرّ عبر دوال التحقق نفسها التي يستخدمها الخادم:

- **عربي فقط**، مع قائمة سماح لللاتيني الحقيقي (رموز العناصر `Fe Au`، فصائل الدم `O AB`،
  اختصارات `HTTP JS`). يُرفض سيريليك/ياباني/صيني/كوري/تايلاندي/عبري.
- **الحرف الأول** محسوب بعد حذف «ال» وتطبيع الألف — لازم يطابق الحرف المخزَّن.
- **النقاط تطابق الصعوبة:** `easy→200`، `medium→400`، `hard→600`.
- **للحروف، الصعوبة محور حقيقي:** سهل = كلمة واحدة، متوسط = كلمتان كحد أقصى، صعب = ثلاث.
- **السؤال لا يحتوي الإجابة**، ولا يذكر الحرف المطلوب.

## الكتابة الآمنة

`append_locked()` تأخذ القفل الحصري، تقرأ، تضيف، تكتب في ملف مؤقت، ثم `os.replace` —
**ذري**، فلا يرى قارئ متزامن ملفاً ناقصاً. تُستدعى **بعد كل دفعة**، لا في نهاية الجولة:
الانهيار يكلّف دفعة واحدة لا كامل التشغيل.

**لا يُسمح بأي كتابة كاملة على `all.json` أثناء التوليد.** قراءة لقطة ثم كتابتها يحذف
صامتاً كل ما أضافته عملية أخرى بينهما. عدد صفوف **نازل** هو بصمة هذا الخطأ.

## الخطط لقطة زمنية

الخطة تسجّل الفجوة لحظة الإنشاء. إن أضاف كاتب آخر أسئلة لنفس الفئة قبل تشغيل الموجة،
تتولّد زيادة. **أعد تشغيل `make_plans.py` بعد أي كاتب آخر لمس البنك.**

الشاردات (الأجزاء) **منفصلة** — شاردان على نفس الفئة = تكرار.

## الحروف: استهدف الحروف القابلة للعب فقط

اللوحة عندها 25 خلية فقط (`LETTERS_25` في `game_letters.html`). الأسئلة تحت حروف ليست
على اللوحة **لا يمكن للاعب الوصول إليها أبداً**. تحقق من قائمة اللوحة قبل التخطيط،
وأبلغ عن اليتامى بدل إعادة تسميتها صامتاً (إجاباتها تبدأ فعلاً بذلك الحرف، فإعادة
التسمية ستكون كذباً).

## إعادة الاستئناف

```bash
python tools/make_plans.py                 # يعيد حساب النواقص من الصفر
python -u tools/run_all_waves.py --workers 6
```

أو شغّل `استئناف-التوليد.bat` من جذر المشروع.

## الفحص بعد التشغيل

- عدد الصفوف يعلو فقط أثناء التشغيل (الانخفاض = كتابة من لقطة قديمة)
- التكرار بمفتاح `game + '|' + norm_ar(question)`
- لا سؤال بـ `category_id` غير موجود في ملف الفئات (سيكون غير قابل للعرض)
- لا حرف فارغ على لوحة الحروف
- لا نص غير عربي في `question` أو `answer`
- التوزيع لكل فئة/حرف/صعوبة مقابل الخطة
